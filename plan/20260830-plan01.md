# 2026-08-30 计划：魔法小镇 + 独立 Agent 运行时

产品从「夏天镇」改为**原创魔法小镇**（气质参考哈利·波特的英国巫师村落，**不用官方地名/校名/商标**）。地图可匿名逛；说话与登记代理人必须登录。

A2A 仍用邮局方案（§5）。模型循环从「薄封装」改为**独立后端 Agent 框架**，可挂内置 LLM，也可挂 Cursor SDK / Codex 等。

## 1. 整体架构（重新梳理）

三层仍是乘法，但中间一层变成完整运行时，不再只是 `streamText`：

```
┌─────────────────────────────────────────────────────────┐
│  小镇壳（现有 Vite/React）                                │
│  地图 · 建筑 · 角色 · /login · /agents · DetailCard 对话   │
└──────────────────────────┬──────────────────────────────┘
                           │ tRPC
┌──────────────────────────▼──────────────────────────────┐
│  小镇 OS（现有 Hono + Drizzle）                           │
│  登录 · agents 注册表 · conversations · 邮局 A2A · 在场   │
│  不负责：推理、工具执行、provider 差异                    │
└──────────────────────────┬──────────────────────────────┘
                           │ AgentRuntime.run(request)
┌──────────────────────────▼──────────────────────────────┐
│  独立 Agent 框架  api/runtime/（新建，可后拆成 package）    │
│  Definition · Prompt · Tools · Hooks · Memory · Provider │
└─────────────────────────────────────────────────────────┘
         │                │                │
    Builtin LLM      Cursor SDK         Codex / 其它
    (AI SDK)      CURSOR_API_KEY      CLI 或 API
```

**小镇 OS 不持模型。** 它只知道：这个 `agentId` 用哪个 `provider`、哪份 `definition`、会话与信封存在哪。  
**框架不持地图。** 它只知道：一轮 run 的消息、工具、hook、记忆读写。

Cursor / Codex 是 **Provider**，不是整镇底座。饮食/健身走 Builtin；符文工坊的 `code` 才走 Cursor/Codex。用户自带 key，禁止用一把团队 key 给路人跑 local（Cursor local 默认自动批准 shell）。

## 2. 独立 Agent 框架要包含什么

> 展开版见 [20260830-plan02-agent-runtime.md](20260830-plan02-agent-runtime.md)：两类记忆主体 × 三个层级、8 个系统 agent 名册、Provider/Hook/Tool 契约与建表改动。

建议目录：`api/runtime/`（先放仓库内，接口稳定后再拆 `packages/agent-runtime`）。

### 2.1 Definition（一份 agent 的静态契约）

```ts
{
  id, kind, slug,
  systemPrompt,          // 人设 + 正面指令（可以问谁、何时用何工具）
  skills: Skill[],       // 按需片段：useWhen / notFor / body
  tools: ToolSpec[],     // 本 agent 业务工具 + 框架注入的 A2A 三工具
  provider: 'builtin' | 'cursor' | 'codex',
  providerOptions,       // model id / cwd / cloud repos
  capabilityTags,        // 门禁：diet 不接 coding
  memoryPolicy,          // 读哪些 key、写入哪些
  hooks: HookName[],
}
```

镇原生三人（fitness / work / diet）与用户登记的一位，都是 Definition。`code` kind 的 Definition 把 `provider` 设为 `cursor` 或 `codex`。

### 2.2 五个基本组成部分

| 部件 | 职责 | 落点 |
| --- | --- | --- |
| **System prompt** | 组装：身份（不可被 compact 掉）+ 人设 + 本轮 skills + A2A 规则（只能走工具） | `PromptBuilder` |
| **Tools** | Zod 入参 + `execute`；业务工具按 kind 注册；框架一律注入 `ask_agent` / `tell_agent` / `handoff` | `ToolRegistry` |
| **Hooks** | `beforeTurn` / `beforeTool` / `afterTool` / `afterTurn` / `onHandoff` / `onError` | `HookBus` |
| **Memory** | 读 `agent_memories`（真相源），编译成摘要再进 prompt；写回结构化 key | `MemoryStore` 适配现有表 |
| **Provider** | 统一 `run({ messages, tools, abort }) → stream` | `providers/builtin` · `cursor` · `codex` |

Hook 先做这几件就够用：

- `beforeTurn`：注入记忆摘要、检查该 agent 是否已有一轮在跑  
- `beforeTool`：A2A 白名单、capability、depth、乒乓 streak  
- `afterTool`：现实动作记账（只有工具成功才允许写信封）  
- `afterTurn`：虚空持球（正文声称「已问」但没有 delegation）  
- `onHandoff`：开对方 conversation + 用户可见纸条  

### 2.3 Provider 接入

| Provider | 适用 | 接入要点 |
| --- | --- | --- |
| **builtin** | 饮食 / 健身 / 工作 / 闲聊 | OpenAI 兼容或 AI SDK；工具 = 本进程 function calling |
| **cursor** | `code`、符文工坊 | `@cursor/sdk` `Agent.create` + `send`；`CURSOR_API_KEY` 来自该用户；MCP/customTools 把小镇工具暴露进去；resume 要重传 MCP |
| **codex** | 同上备选 | Codex CLI 子进程或官方 API；和 Clowder 一样当「会干活的手」，不当时尚 OS |

OS 对框架只调：

```ts
runtime.run({
  agentId, userId, conversationId,
  userMessage,
  definition,          // 含 provider
})
```

A2A worker 对**被问的** agent 再调一次 `runtime.run`，`depth=1`，不再允许 Ask。

第一期不上 LangGraph。框架自己管回合；邮局管跨 agent。

## 3. A2A（保留现有参考，不改方向）

镇内 = 异步信封，三种：`ask` / `tell` / `handoff`。用户是委托人。只传记忆摘要。

已有 `delegations` 表。待补：`type` · `depth≤1` · `expiresAt` · 熔断计数 · 仅工具写入 · capability 白名单 · 回写发起方 `messages`。

Clowder 要搬的纪律不变：球权单值、现实动作、虚空持球、乒乓 2/4、不要文本 @、交接必须看得见、投递/持球/终局同一套生命周期。不搬他们的 Queue/CLI/全员 Thread。

外站用户 agent（自己的 URL / Cursor 云）后做：邮局当网关再译协议。

## 5.10 GenericAgent 可借鉴（`D:\GenericAgent` origin/main `efb3bc6`）

2026-08-30 已 `git fetch`：远端 `origin/main` 仍停在 `efb3bc6`（desktop 2.0）。本地工作区 `ahead 663 / behind 1231` 且大量 UU 冲突，**没有执行 merge**，只读远端。

值得搬进 `api/runtime` 的，不是它的电脑控制工具：

| GenericAgent | 我们怎么用 |
| --- | --- |
| ~100 行 `agent_runner_loop`：LLM → tools → 拼下一轮 user | `runtime.run` 保持同样薄 |
| `StepOutcome(data, next_prompt, should_exit)` | 工具只返回结果 + 下一轮 user 补丁，不自己聊 |
| `plugins/hooks.py`：`agent_before` / `turn_before` / `llm_before|after` / `tool_before|after` | 对接已规划的 HookBus；插件目录自动 discover |
| `tools_schema.json` 与人设分离，传给 `client.chat(..., tools=)` | Definition.tools + Prompt 分开 |
| `update_working_checkpoint` 短记事本（短任务别反复写） | 写入 `agent_memories` 的工作切片 |
| `start_long_term_update` 长任务结束后才结晶 | 长期记忆，不要每轮灌全量 |
| 历史压缩 / trim；每 10 轮清一次 last_tools | 会话变长时摘要，不把全程塞给模型 |
| `ask_user` + 连续空转 3 次退出 | 对应 Handoff 要用户点头；防止空转烧 token |
| 不预装一堆 skill，用完再结晶 | 镇原生先给小 skill；用户 agent 后长 |
